ML-KEM Implicit-Rejection Assessment

FIPS 203 ML-KEM-768 · Two independent implementations · liboqs 0.16.0 (C) vs kyber-py 1.2.0 (pure Python)

Result: 19/19 differential cases PASS, 20/20 valid-encapsulation rounds PASS, zero cross-implementation disagreements — in two independent runs. For every rejected 1088-byte ciphertext, both implementations return the same 32-byte secret, and it equals the implicit-rejection fallback K̄ = J(z ║ c) (SHAKE256) recomputed independently. Both implementations refuse a decapsulation key whose stored H(ek) fails the FIPS 203 §7.3 hash check, and both refuse wrong-length ciphertexts and keys. No measurable success-vs-failure latency difference above noise was found in either implementation — which is a measurement result, not a proof of timing indistinguishability.

What was tested

Parameter set ML-KEM-768 (ek 1184 B, dk 2400 B, ct 1088 B, ss 32 B). A deterministic test keypair (key_derive from a public seed) is shared by both implementations; a second, random liboqs-generated keypair is cross-checked in the other direction. The differential harness (src/run_differential.py) covers:

  • Valid (1 case + 20 rounds): encapsulation under the test keypair; both implementations must return the encapsulation shared secret, in both directions (kyber-py encap, liboqs encap, liboqs keypair).
  • Malformed (14): truncated ciphertexts (1087, 512, 1, 0 bytes), extended ciphertexts (1089, 2048 bytes), single-bit flips at bytes 0, 543, 1024, 1087, all-zero, all-0xFF, and two seeded-random ciphertexts.
  • Adversarial (4): a valid ciphertext under a different keypair, u-part saturated to 0xFF, v-part saturated to 0xFF, u-part zeroed — all crafted so the re-encryption check must fail.
  • Input checks (6): corrupted stored H(ek) in the decapsulation key, truncated/extended decapsulation keys (2399, 2401 bytes).
  • Determinism: 5 repeated decapsulations of the same input per implementation, valid and malformed.
  • Timing: n=100 decapsulations per implementation per outcome (success vs failure), wall-clock, AMD EPYC 9D25, Linux 7.0.0-43-generic x86_64.

Logs contain SHA-256 digests of shared secrets and ciphertexts only — never raw shared secrets. Test keypairs are generated from a public seed; they are test vectors, not real keys.

Findings (severity-ranked)

IDSeverityFinding
F-01Medium liboqs OQS_KEM_decaps performs no ciphertext/key length check; callers must validate. The C API takes bare pointers with no lengths (src/kem/kem.h: “Caller is responsible for allocating sufficient memory”), so the FIPS 203 §7.3 type checks cannot be performed by the library function itself. The driver enforces them before calling (1087-byte ct refused; 2399/2401-byte dk refused). A caller passing a short buffer directly gets no refusal from the library.
Evidence: outputs/run1/differential-run.log (input checks); src/mlkem-liboqs-driver.c; liboqs 0.16.0 src/kem/kem.h.
F-02Low Error-signalling conventions differ at the API boundary. kyber-py raises ValueError; the liboqs path returns an error status (decaps returned -1 for a corrupted stored H(ek)) or a driver-level refusal string for wrong lengths. Both refuse; integrators must handle both channels.
Evidence: outputs/run1/results.json, input_checks.
F-03Low Implicit rejection is byte-identical across implementations. All 14 malformed and 4 adversarial 1088-byte ciphertexts return the same secret from both implementations, equal to J(z║c) recomputed independently with hashlib.shake_256. Valid encapsulations agree 20/20 rounds in both directions.
Evidence: outputs/run1/results.json (expected_fallback_sha256 matches both implementations in every rejected case).
F-04Low No success-vs-failure latency difference above noise. See the timing table above. Measurement result only — not a proof of indistinguishability.
F-05Low Both implementations perform the §7.3 decapsulation-key hash check on every decapsulation. A dk with corrupted stored H(ek) is refused by both. Source-confirmed: kyber-py _decaps_internal raises; mlkem-native mlk_kem_check_sk returns MLK_ERR_FAIL (called from mlk_kem_dec).
Evidence: outputs/run1/results.json, input_checks; citations.md §3.

Not found: no case where the implementations disagreed on a returned secret; no rejected ciphertext returning anything other than J(z║c); no correctly-sized input for which decapsulation returned an error instead of a 32-byte secret; no timing delta above noise.

Reproduce

./run_all.sh <run-name>

Builds liboqs 0.16.0 from the bundled tarball (SHA-256 verified), compiles the driver, installs kyber-py 1.2.0 from the bundled wheel (no network needed), and runs the differential harness into outputs/<run-name>/. A clean reproduction from a fresh copy of this repository is outputs/run2/; outputs/run-comparison.log confirms every verdict, agreement, fallback equality, and input-check outcome is identical between runs.
